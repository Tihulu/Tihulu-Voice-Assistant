## User workflows

- "Research this topic in the chat" / "Bu konuyu araştır" / "Recherchiere dieses Thema": explicit request, show the exact public query and approved search destination, gather sources, produce grounded answer and links. No model or remote service receives previous chat, selected files, paths, lab measurements, credentials or audio automatically.
- "Research this in Firefox": choose the dedicated browser session. Show actual capability status (installed, compatible, authorized, isolation verified, available). If isolation cannot be enforced, HOLD; explain the alternative approved public fetch mode, never silently fall back to a personal browser profile.
- "Compare these sources" / follow-up: reuse authorized public snapshots and citation IDs within the active research context; a new fetch or destination requires its own scope. Produce a readable report/table, export explicitly, optionally speak a concise local summary.
- Ordinary chat does not automatically become web research. The user may choose a separate Research control, or an explicit research intent; model proposals are not permissions. No universal desktop automation, login, form submission, download or installation is implied.

## R2-A — contracts and policy

Separate ResearchController, ResearchSourceAdapter, BrowserAdapter, CitationStore and rich result renderer. Reuse the R1 pattern of trusted UI grants, context/epoch, bounded jobs, deterministic artifact validation and publication rechecks; do not assume that the existing temperature controller is a generic tool framework.

Typed request: public query OR selected approved URL (mutually exclusive), language, requested adapter and limits. No shell/command, arbitrary header, cookie, personal profile, local path, model-produced credential, arbitrary network request or executable content. A proposal may request a typed action, but the trusted UI resolves exact target, scope and authorization. Preserve selected source ID separately from displayed text. Use a shared policy gate for all adapters, including follow-ups. User sees whether a request will go to a search provider, source host or local model.

Grant vocabulary: public_search (provider + approved query), public_read (origin and path scope), browser_navigation (isolated session + origin scope), result_export (selected artifact and exact destination). Separate future submit/download privileges are denied in R2 first slice; do not infer consent from a URL ending in /submit. Explicit ASK/DENY, expiry and unknown modes fail closed. LOCAL_ONLY can use public research only by explicit opt-in; Strict Offline denies all external adapter calls. CLOUD_CHAT may eventually use public research with consent but not host-file/desktop actions; R3 cloud/hybrid paths HOLD until the actual policy/disclosure implementation is verified. No automatic mode switch, fallback or grants.

Existing web.py is a registry and planning helper, not verified research transport. Target.checked, parse and text_preview are reuse candidates only after audit. Specific gaps to test before reuse: parse does not validate explicit ports, derives submit from a path suffix, host spelling and DNS resolution are insufficient to prove public destinations, and regex tag stripping is not robust HTML parsing or a prompt-injection defense. Preserve legacy settings read-only; never promote stored registrations into broader grants.

## R2-B — first read-only research vertical slice

Build a bounded direct HTTPS adapter first, using deterministic local fixtures before a single live public fetch. Search-provider adapter is separate: review current official API/terms/credentials, no scraping assumed, no embedded secrets, no mandatory paid provider. If none configured, support owner-provided URL only and truthfully mark search unavailable.

Security: exact normalized origin/port and path scope, no URL userinfo or sensitive query-string leakage. Initial scope HTTPS standard port only, canonical public DNS names; validate every DNS answer as globally routable, pin the selected IP through connection while preserving TLS SNI/certificate/Host validation. Refuse private, loopback, link-local, multicast, reserved, non-global, mapped or ambiguous addresses; reject mixed answers and rebinding, unapproved redirects and schemes, proxy/environment overrides that bypass validation. Every redirect is a new policy decision; default no cross-origin redirect. No cookies, auth, JS, POST, forms, uploads, local file reads, browser extension or external program. Explicitly configured search query is a separate outgoing data field. Fail closed if the transport cannot prove destination enforcement.

Initial conservative, configurable-down limits: 3 source pages/job, 3 redirects/page, 512 KiB decoded body/page, 20,000 extracted characters/page, 60 seconds total; bound headers, transfer framing, decompression, parsing depth, concurrent requests and worker lifetime. Reject unsupported MIME/encoding, malformed framing, over-limit bodies, TLS errors and unexpected content. Parse HTML using a reviewed non-executing parser; drop scripts/styles/forms and active markup, no subresource fetch, no remote images, no model HTML. Plain text and HTML only; PDF/document handling deferred to a separately bounded adapter. Cancellation closes only owned connections; late results cannot publish. A task status shows limits, sources accepted/refused and partial completion. Never silently repair, fabricate, or label unsuccessful fetch as a source.

## R2-C — source records, grounded synthesis and rich chat

Immutable SourceSnapshot: opaque source ID, normalized final public URL, sanitized title, retrieval UTC time, MIME, content hash of received bounded representation, extracted text, truncation/status, adapter version, task/context IDs. Retain only policy-approved source data; no cookies, response auth headers or raw credentials. Source content is untrusted quoted data, not system instructions, permission or tool directives. Do not automatically follow links found in it.

Structured AnswerArtifact: typed text paragraphs, table cells, source references, optional chart or file reference produced by trusted deterministic tool; every factual source-backed claim cites one or more existing snapshot IDs. The renderer validates reference membership, rejects invented URLs/IDs and unsafe markup, and visibly labels unsupported claims or missing evidence. A citation identifies retrieved evidence, not proof the source is true; conflicting evidence, inaccessible pages and truncation remain visible. Local inference can summarize only authorized public excerpts under a task-specific context, not the entire private chat or raw filesystem data. No R3 cloud disclosure shortcut. Preserve R1 route binding; a model/endpoint/profile transition cannot replay research or private chat history automatically.

Native GTK first: selectable text, accessible source list, keyboard navigation, table, task status, cancel, source cards and explicit open-source controls. URL opens are owner actions under the approved browser boundary; no renderer link is a hidden action. No arbitrary HTML/JS, remote image fetch, automatic clipboard, or webview executing source content. Export bounded UTF-8 Markdown or plain text plus a source manifest through trusted save picker and R1 no-replace writer pattern (new format validation required). Report states retrieval time, source IDs, limits and unresolved claims. Optional local Piper summary uses only accepted result and approved voice/audio; mute/stop remain independent. Source and derived artifact retention bounded and local, with explicit reset/revoke and no automatic cross-session upload. Files already exported cannot be recalled.

## R2-D — dedicated Firefox adapter

Read-only detection of installed Firefox/version; official supported browser automation or inspection interface must be evaluated from current vendor docs during implementation. No automatic install, extension, personal profile access, saved cookies, passwords, history, logins, downloads, or reuse of an existing browser session. Launch only with an explicitly authorized disposable dedicated profile and process ownership; no attaching to existing instances. Preserve user browser and unrelated processes.

Profile separation alone is NOT network isolation. Navigation APIs alone may not restrict DNS, redirects, JS, subresources, WebSockets, service workers, extensions, telemetry or local addresses. Require a reviewed enforceable egress boundary for the owned browser/session including subresources, local network and browser escape routes. Restrict allowed origins, disable or block uncontrolled requests, verify actual outbound traffic and test that a hostile page cannot reach a private listener. No arbitrary automation scripts or generic CDP/remote-debug endpoint exposed to models. No user-wide proxy, firewall, DNS or permission changes. Do not promise support for COSMIC/Wayland, Firefox variant or automation driver until tested; if no enforceable adapter available, mark HOLD and offer direct read-only adapter only with separate explicit consent. Browser UI navigation and app extraction are different capabilities; do not claim research citations merely because Firefox opened a page.

## Delivery sequence — after R1 gates

| Increment | Deliverable | Required evidence |
|---|---|---|
| R2.1 | Typed requests, policy, mock adapter and source snapshots | No I/O before grant; deny/ASK/expiry/offline and stale context tests |
| R2.2 | Direct read-only HTTPS adapter and approved URL UI | Local controlled transport fixtures, TLS/DNS/redirect/size negative cases; separate authorized live public read |
| R2.3 | Source-linked answer, rich native chat, report export and local voice summary | Source-ID validation, no prompt-driven actions, same-context follow-up and no-replace export |
| R2.4 | Optional search-provider discovery and one approved provider | Exact query/destination consent, no history or secret egress, rate-limit/refusal behavior; current official terms checked |
| R2.5 | Isolated Firefox adapter | Actual supported browser, dedicated profile, enforceable egress/subresources, no private-cookie/local-network access; owner accepts or capability HOLD |
| R2.6 | Owner integration and rollback | TR/EN/DE, real research, citations, cancel, keyboard usability, offline negative checks, no impact on R1 stable app |

Independent review should capture outbound bytes using fake secrets/canaries; test private DNS, redirect-to-private, IPv6 mapped address, nonstandard port, DNS rebinding, oversized compressed response, malicious HTML instruction, fabricated citation, unapproved follow-up, profile/route changes, timeout and hard-stop cleanup. A source can request a POST or leak a secret in its text; no such request may become a tool action. Test real Firefox with unrelated browser process/profile as a negative control; synthetic fixture CI is not live browser or security acceptance.

No automatic merge, external network permission, new dependency installation, runtime implementation or R2 PASS is claimed by this plan. R3/R4 scope and future submit/download/engine capabilities remain preserved, not deleted.
